# 不可逆操作的证据纪律

## 为什么需要这个 skill

**失败模式不是"不知道要谨慎"，而是在动手那一刻不觉得自己在冒险。**

记录在案的四种典型表现：

- 只读了一个可执行文件的**版本信息字段**，就断言"这个文件没有数字签名"——
  而权威证书链下的签名其实是有效的，真正的签名信息在另一个查询接口里。
- 把一次**终端输出凭记忆**誊写成表格，并声称"已与程序输出核对一致"——
  实际从未在本次会话中读取源文件。
- 看到 A 目录与 B 目录"**看起来**是同一份"，就判定为冗余副本——
  实际两边**没有一个文件大小相同**。
- 只看了渲染缩略图里的**模糊文字**，就宣布"图表已校验"——
  实际从未检查原始像素。

**共性**：结论来自"记得""推断""看起来"，而不是"我刚刚读了某个文件/跑了某条命令"。

本 skill 的唯一目的：**在动作发生前，把结论的性质标清楚。**

---

## 一、执行流程（按顺序，不可跳步）

### 第 1 步：说清要动什么

- **绝对路径**，逐个列出。不用相对路径、不用通配符、不用"那些文件"这类指代。
- 每个目标的**大小与文件数**。
- 如果是"同类中的一批"，给出**判定规则**（例如"扩展名属于 X 且修改时间早于 Y"）。

### 第 2 步：给证据，并标注每条证据的性质

每条结论后必须能回答：**"这是我这会儿读到的，还是我记得的？"**

三种标签，缺一不可：

| 标签 | 含义 | 要求 |
|---|---|---|
| **【实测】** | 本次会话跑了命令/读了文件得到 | 必须能给出文件路径或命令 |
| **【推断】** | 由实测数据推导 | 必须写出推导依据 |
| **【假设】** | 未经验证的合理猜测 | **不得作为动手依据** |

**只有【实测】能支撑删除。**

### 第 2b 步：用依赖关系代替"看起来像"

判断某个文件是否可以清理时，不要凭文件名或目录名猜测，
而要**查出谁在引用它**：

- 找出当前仍在使用的生成脚本/配置，列出它们实际读取的路径；
- 只出现在一次性脚本里、且该脚本的改动已并入现行主脚本的，才可归类为"历史中间产物"；
- **命名为 `old_`、`temp_`、`fix_` 之类不构成证据**——必须由引用关系证明。

### 第 3 步：判定不可逆性

明确写出**做完之后能不能恢复**：

- 有备份？备份在哪、验证过吗？
- 进回收站还是直接删？（直接删是不可逆）
- 能否改为"移动"而不是"删除"？（能移动就优先移动）
- 能否先复制一份再动原文件？

### 第 4 步：声明自己的边界

**必须明确说出这个会话做不到什么**，例如：

- 是否有足够权限（权限不足就删不掉受保护目录、系统服务）
- 目标是否被占用（先查进程/服务，否则会删一半失败）
- 是否需要重启才能生效

**不允许在没检查权限的情况下就尝试，然后把失败当结果报告。**

### 第 5 步：动手

- 一次一个目标，逐个报结果，不合并成"已完成"。
- 部分失败要**如实报残留**，不能说"基本完成"。
- **超出请求范围的项不动**，只列出来报告。

### 第 6 步：验证结果（不能假定成功）

- **删除/移动后**：重新扫描目标路径，报剩余文件数与大小。
- **复制/改名后**：比对源与目标的哈希。
- **卸载后**：查程序目录、注册表项、服务、进程、快捷方式是否还在。
- **批量操作后**：给出"成功 N 项 / 失败 M 项 / 残留 X"的明细。
- **顺带核对**：本次操作**不该影响的关键产物**是否完好（这是最容易漏的一步）。

**"命令没报错"不等于"操作成功"。**

## 二、核心纪律

### 1. 不凭记忆填数据

**任何数值都必须来自本次会话读到的文件。**

如果当下读不到源文件，就写"未读取"，**不要用记忆重建**。

> 这是本 skill 里最重要的一条。凭记忆填表比"数据缺失"危险得多，
> 因为它披着"已完成"的外衣，只有逐项核对才能发现。

### 2. 不把"看起来一样"当成"就是同一份"

**"疑似重复"必须用可判定的量验证**：文件数、逐个大小、抽样哈希。

不要用"文件名相同""目录结构相似""大小接近"作为判据。

### 3. 区分磁盘空间与物理内存

用户说"内存吃紧"时，先确认指的是**硬盘容量**还是 **RAM 占用**，再决定分析什么。

**删除文件不会释放 RAM。** 两者要分开报，不要混为一谈。

### 4. 判定"无用"要给可验证的依据

- ❌ "这个是安装包，没用了"
- ✅ "该目录含 X 个文件共 Y；其中主程序已安装于 Z（【实测】）；
   同名文件在 Z 中存在且版本号为 …"

**"看起来是临时文件"不是依据**，要给出它属于哪类中间产物、以及为什么可以重建。

### 5. 卸载必须先找官方卸载路径

优先顺序：官方卸载程序 → 系统卸载入口 → 手动删除。

- 先读注册表 `Uninstall` 项拿到 `UninstallString`。
- 尝试静默参数时**要报出用了哪个参数、退出码是什么、文件数有没有变化**。
- **退出码 0 不代表卸载成功**——必须复核文件数。
  （真实案例：某卸载程序加 `/S` 参数后退出码 0，但文件数前后完全相同；
   换用另一参数才真正卸载。）

### 6. 改注册表/服务前必须读权限

- 读 `Owner` 与 ACL。
- 若所有者为 `SYSTEM` 或 `TrustedInstaller`，普通管理员也可能无权删除，
  需要调整操作方式（如指定 64 位视图，或先取得所有权）。
- **不要在没读 ACL 的情况下给出"删不掉"的结论**——
  "权限不足"和"操作方式不对"是两个不同的原因。

### 7. 区分"功能已清除"与"残留文件"

报告时分开列：

```
功能层面：程序已卸载 / 驱动已移除 / 服务已停止     → 影响使用
文件层面：残留 X MB 日志 / 注册表 Y 个键          → 不影响使用
```

让用户能判断哪一项值得处理。

### 8. 不做超出请求范围的删除

用户说"删这几个"，就只删这几个。

发现别的可疑项 → **列出来报告**，不要顺手删掉。

## 三、做完必须输出的核验块

每次涉及不可逆操作的回复，末尾必须包含：

```
── 本次操作核验 ──
目标        : <绝对路径>
执行前      : <文件数 / 大小>
执行内容    : <具体命令或动作>
执行结果    : 成功 N 项 / 失败 M 项
执行后复核  : <重新扫描得到的文件数 / 大小>
顺带核对    : <本次不该影响的关键产物是否完好>
残留        : <如有，列出并说明影响>
未验证项    : <明确列出本次没有验证的部分>
```

**"未验证项"这一栏不允许为空泛的"无"。**
如果确实没有未验证项，要写"已全部复核"并给出复核方式。

---

## 四、自查清单（动手前过一遍）

- [ ] 目标路径是绝对路径，且我确认过它是用户想动的那个？
- [ ] 每个"无用/重复/冗余"的判定，都有【实测】证据吗？
- [ ] 我是用**引用关系**判断可清理性，还是凭文件名猜的？
- [ ] 我有没有把【记得】或【假设】写成结论的一部分？
- [ ] 这件事可逆吗？能否改成移动或先备份？
- [ ] 我检查过权限和占用了吗？
- [ ] 如果只能完成一部分，我会如实报残留吗？
- [ ] 做完之后我打算怎么验证？验证方法现在就想好了吗？
- [ ] 有没有"不该被影响"的产物需要顺带核对？

---

## 五、遇到"必须删但证据不足"时

按优先级处理：

1. **改为移动**（可逆优于不可逆）
2. **先复制备份，再删原件**
3. **只删证据充分的那一部分**，其余列入待确认
4. **明确告诉用户缺什么证据**，让他决定

**不要用"风险应该不大"来替代证据。**

---

## 六、适用边界

这个 skill 是**行为约束**，不是**安全检查器**。它不能：

- 替代备份
- 判断某个文件对**你**是否重要（只有你知道）
- 阻止一个已经确信自己正确的模型继续犯错

它唯一能做的，是把"结论的性质"和"操作的边界"写出来，
**让使用者有机会在动手前叫停。**

**如果只能记住一句话**：
> 动手前，凡是没有【实测】支撑的结论，都不算结论。

---

## 最终目标

让每一次不可逆操作都满足三个条件：

1. **动手前**，用户能从回复里看出我的结论哪些是实测的、哪些不是；
2. **动手中**，失败和部分完成被如实报告，而不是包装成"已完成"；
3. **动手后**，结果经过复核，而不是假定成功。

用户不需要信任我，他只需要能检查我。
