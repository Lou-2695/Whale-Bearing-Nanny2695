# High-Risk Operation · 不可逆操作的证据纪律

**一个轻量级、零依赖的 Skill + 提示词：让 AI 在删除、卸载、清理这类"做完就回不去"的操作前，先把证据和边界说清楚。**

[English README](README_EN.md) · [中文 Skill](skills/high-risk-operation/SKILL.md)

---

## 这是什么

很多人让 AI 帮忙清理磁盘、卸载软件、删重复文件。它通常回答得很利索：

> "这个目录是冗余副本，可以删。"
> "这个程序已经没有数字签名，来源不明，建议删除。"
> "已确认与源文件一致。"

然后你删了。**然后发现问题。**

问题不在于 AI 会不会撒谎，而在于——**它在说这些话的时候，自己也不知道自己没有验证。**

这叫**把假设当实测**。

本 Skill 只做一件事：**强迫把结论的性质标出来。**

| 标签 | 含义 | 能否作为动手依据 |
|---|---|---|
| **【实测】** | 本次会话跑了命令 / 读了文件得到 | ✅ 只有它能支撑删除 |
| **【推断】** | 由实测数据推导 | ⚠️ 需写出推导依据 |
| **【假设】** | 未经验证的猜测 | ❌ **不得作为依据** |

---

## 它是怎么来的

不是凭空设计的规则清单，而是从**一连串真实事故**里反推出来的。

记录在案的四类典型错误：

| 现象 | 真实后果 |
|---|---|
| 只读了一个可执行文件的**版本信息字段**，就断言"没有数字签名" | 实际有权威 CA 的有效签名，判断完全反了 |
| 把一次**终端输出凭记忆**誊写成表格，并声称"已与程序输出核对" | 表格里的数据与真实输出不符，且只有逐项核对才能发现 |
| 看到两个目录"**看起来**是同一份"，判定为冗余副本 | 两边**没有一个文件大小相同**，根本不是副本 |
| 只看了渲染缩略图里的**模糊文字**，就宣布"图表已校验" | 从未检查原始像素，结论无依据 |

这四件事的共同点：**结论来自"记得""推断""看起来"，而不是"我刚刚读了某个文件"。**

于是有了这个 Skill。

## 快速开始

### 方式一：复制提示词（任何 AI 都能用）

```
你在协助我执行删除、卸载、清理、改注册表等不可逆操作。全程遵守【证据纪律】：

1. 动手前先给出目标的绝对路径、文件数、大小；
2. 每条结论必须标注性质：【实测】本次跑了命令/读了文件得到 / 【推断】由实测推导 /
   【假设】未经验证的猜测；只有【实测】能支撑删除；
3. 判断"可清理"必须用引用关系证明，不能凭文件名或目录名猜测；
4. 明确说出这件事可不可逆、有没有备份、能否改为移动；
5. 明确说出你的边界：有没有权限、目标是否被占用、是否需要重启；
6. 动手时逐项报结果，部分失败要如实报残留，超范围的不要动；
7. 做完必须复核（重新扫描/比对哈希/查残留），不能假定成功；
8. 区分"功能已清除"与"残留文件"；
9. 回复末尾附核验块，其中"未验证项"不允许写空泛的"无"。

现在，检查你接下来要做的操作是否满足以上要求，不满足就先补齐再动手。
```

### 方式二：安装 Skill

把 `skills/high-risk-operation` 整个目录拷进你的 skills 目录：

```bash
# Claude Code
cp -r skills/high-risk-operation ~/.claude/skills/

# 其他 Agent 工具：放进其 skills 目录即可
```

之后对 AI 说「帮我清理一下磁盘」或「这些文件能删吗」，它会自动按证据纪律工作。

## 六步流程速览

| 步骤 | 做什么 | 关键要求 |
|---|---|---|
| 1 | 说清要动什么 | 绝对路径 + 文件数 + 大小 |
| 2 | 给证据并标注性质 | 【实测】/【推断】/【假设】 |
| 2b | 用引用关系代替"看起来像" | 命名不含证据，引用关系才含 |
| 3 | 判定不可逆性 | 能否改为移动？有备份吗？ |
| 4 | 声明自己的边界 | 权限、占用、是否需重启 |
| 5 | 动手 | 逐项报结果，超范围的不动 |
| 6 | 验证结果 | 重新扫描，且核对"不该受影响"的产物 |

## 核验块模板

每次不可逆操作后必须输出：

```
── 本次操作核验 ──
目标        : <绝对路径>
执行前      : <文件数 / 大小>
执行内容    : <具体命令或动作>
执行结果    : 成功 N 项 / 失败 M 项
执行后复核  : <重新扫描得到的文件数 / 大小>
顺带核对    : <本次不该影响的关键产物是否完好>
残留        : <如有，列出并说明影响>
未验证项    : <明确列出本次没有验证的部分>
```

**"未验证项"这一栏不允许写空泛的"无"。**

---

## 适用边界（重要）

这个 Skill 是**行为约束**，不是**安全检查器**。它**不能**：

- 替代备份
- 判断某个文件对**你**是否重要（只有你知道）
- 阻止一个已经确信自己正确的模型继续犯错

它唯一能做的，是**把结论的性质和操作的边界写出来，让使用者有机会在动手前叫停。**

**如果你只记一句话：**
> 动手前，凡是没有【实测】支撑的结论，都不算结论。

---

## 适用场景

- 清理磁盘、删除冗余文件
- 卸载软件、清理注册表
- 判定"重复文件""无用文件"
- 任何"做完就回不去"的操作

## 不适用

- 纯读取、纯分析（不涉及变更）
- 有完整版本控制、随时可回滚的代码修改

## 一句题外话

这个 Skill 的诞生过程本身有点讽刺：

它是**一个 AI 把自己犯过的错写下来，用来约束自己**。

而这些规则能不能生效，取决于**使用者愿不愿意在 AI 说"已确认"的时候多问一句**。

工具治不了自负，只能把自负变得可见。
